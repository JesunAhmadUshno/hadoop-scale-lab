# Audit

Author's audit of this build against the programme charter.
State at audit time: Phase 1 complete; Phase 2 (all timed runs)
blocked on SSH access to the machine of record, verified live on
2026-11-08 (BlackBoxV2 hop answers with its hostname; the R610
answers Permission denied (publickey), exactly the expected state
until the coordinator key is installed).

## Charter gates

1. Pre-registration before results. PREREGISTRATION.md is the
   first content commit (d06513e), written before any code, corpus
   processing, or run existed. Git history shows the order.
2. Correctness before speed, in code. The Phase 2 driver
   (scripts/run_study.py) hashes every run's canonical output and
   voids the cell on any mismatch with the baseline; the void is
   written to the raw run log. The same equality is exercised
   without a cluster by tests/test_equivalence.py: both jobs,
   through a local pipe (mapper, sort, combiner, sort, reducer),
   match the DuckDB baseline byte for byte after canonical
   sorting, including a zero-token document and Unicode text.
   The same check on a real-corpus slice (the first 20,000
   extracted Wikisource documents, 210 MB of text) also passes:
   inverted index 240,682 term lines, canonical SHA-256
   7ce34177947e98199edde3a2448aded757f1136b6767422329b8dd0d04823747
   for both arms; bands SHA-256
   2b2e4120da77d32e975f2fd8c7d916b3d3f52caac79a273d3f9254f15a61c8ed
   for both arms.
3. One tokenizer, both arms. src/common.py is imported by the
   Streaming jobs (shipped with -files) and by the baseline, so
   tokenization cannot drift between arms.
4. Corpus integrity. One file, downloaded from the pinned dated
   dump directory; MD5 verified against the publisher's checksum
   file by scripts/fetch_corpus.sh; SHA-256 recorded in
   results/corpus_manifest.json before any run.
5. Numbers come from scripts. RESULTS.md is generated by
   scripts/make_results.py from results/raw_runs.jsonl; with no
   runs it generates the awaiting-runs state rather than a
   template a human could quietly fill.
6. No substitute machines. Nothing timed was run on the
   development VM. Its only outputs are correctness results,
   which carry no times.
7. Spend and credentials. Zero spend: every tool is local and
   open source; the corpus is a public dump. No credential was
   created or used. The R610 password was never written to any
   file in this repository or used in Phase 1.

## Deviations and incidents on record

- DECISIONS.md D1: the corpus is the English Wikisource articles
  dump, not the brief's recommended Wikipedia abstracts dump,
  because Wikimedia no longer publishes abstract dumps (the
  historical URL returns 404, verified 2026-11-08). The brief's
  fallback rule (real text, one file, checksum, nested subsets)
  is followed exactly.
- DECISIONS.md D2: zero-token documents fall in no length band;
  both arms exclude them identically via the shared band
  function.
- The cluster stack (docker-compose.yml, docker/) has never been
  executed: the development VM has no Docker. Image build,
  config mounts, daemon startup, the Streaming jar path, and
  YARN counter display names are all written from the Hadoop
  3.3.6 documentation and the pinned image layout, and are
  unverified until Phase 2's preflight runs on the R610.
- scripts/run_study.py's cluster paths (ingest, counter parsing,
  fsck block counts, output collection) are likewise unrun.
  Its non-cluster paths (canonical hashing, layout splitting)
  are covered by tests.
- Jev claim_check: the client is present
  (~/workspace/tools/jev/jev_gate.py) but was not run, because
  there are no headline verdicts to check yet. It runs at
  Phase 2 close, on the measured verdicts, and its model,
  noul, and route will be recorded here and in RESULTS.md.

## Grade: 3,400 of 10,000 (Phase 1 state)

Deductions, itemized:

- 4,000: no measured results. H1 to H4 are all untested; the
  study's core deliverable (the numbers) does not exist yet.
  This is a blocked state, honestly labelled, not a shortfall
  that wording can soften.
- 1,200: the Compose cluster has never run anywhere. Daemon
  startup order, the config mount, the derived image build, and
  python3 availability inside task containers are unverified.
- 600: the Phase 2 driver's cluster-facing code paths are
  untested end to end (counter display-name parsing, fsck
  parsing, large-output collection).
- 300: the Spark arm (H4) is written but its YARN submission
  path from the apache/spark client image is unverified.
- 200: corpus substitution (D1). Forced by the source, fully
  documented, but the abstracts corpus was the brief's first
  choice and the switch is a deviation.
- 150: the baseline moves token rows into DuckDB through a
  temporary CSV; honest and documented, but it is the known
  inelegance a reviewer will find first at the 5 GiB scale.
- 150: Jev claim_check deferred to Phase 2 close (no claims
  exist yet); the gate is scheduled, not skipped.

What the grade credits: a genuinely locked pre-registration with
decidable pass lines; a checksum-equality regime implemented in
the driver, not just promised; byte-equivalence of both jobs
proven on this machine and on a real-corpus slice; a capped,
isolated cluster design that cannot squeeze the host's other
duties; and an awaiting-runs RESULTS.md that cannot be mistaken
for results.
