# Audit

Author's audit of this build against the programme charter.
State at audit time: Phase 2 complete. The timed matrix ran on
the machine of record (Dell R610, Ubuntu 24.04.5, 94 GiB RAM,
16 cores) on 2026-11-08 and 2026-11-09, and the compose cluster
was torn down at close. Verdicts were computed by
scripts/make_results.py from results/raw_runs.jsonl under the
rules frozen in PREREGISTRATION.md: H1 CONFIRMED, H2
INCONCLUSIVE (cell not measured), H3 INCONCLUSIVE, H4 REFUTED.

## Charter gates

1. Pre-registration before results. PREREGISTRATION.md is the
   first content commit (d06513e), written before any code,
   corpus processing, or run existed. Git history shows the
   order. The document was not edited during Phase 2; every
   adaptation lives in DECISIONS.md (D3 to D13), recorded before
   the runs it affected.
2. Correctness before speed, in code. The driver hashed every
   run's canonical output and voided any cell whose SHA-256
   differed from the baseline reference. Across the final
   matrix (60 run records: 15 warm-up, 45 timed), zero runs are
   marked void and every timed run's hash equals its baseline
   reference, including all four Spark runs. One cell is
   recorded as a void_cell: the H2 small-file cell, stopped
   unmeasured (D10).
3. One tokenizer, both arms. src/common.py is imported by the
   Streaming jobs (shipped with -files), by the Spark job
   (shipped with --py-files, D13 addendum 3), and by the
   baseline, so tokenization cannot drift between arms.
4. Corpus integrity. The dump's SHA-256
   (bb9318dd1045cd0e0f0e5ea9329b1d61a639590758427fd4275a2926fa6a5272)
   was re-verified on the R610 on arrival, before any run, and
   matches results/corpus_manifest.json. The extraction
   manifest is committed as results/extraction_manifest.json:
   648,182 documents, 1,984,437,310 bytes of extracted text.
5. Numbers come from scripts. RESULTS.md is generated by
   scripts/make_results.py from results/raw_runs.jsonl,
   results/host_state.json, and results/layouts.json. Medians,
   ratios, penalties, and verdicts in RESULTS.md and in this
   audit are the script's, cross-checked by hand arithmetic.
6. No substitute machines. Every timed cell ran on the R610.
   Development machines ran correctness checks only, which
   carry no times.
7. Spend and credentials. Zero spend: every tool is local and
   open source; the corpus is a public dump. No credential was
   created. The standalone Python tarball used by the Spark
   executors (D13) is a public release artifact, hash-recorded.

## Deviations and incidents on record (Phase 2)

Phase 1 items D1 (corpus substitution) and D2 (zero-token
documents) stand as recorded. Phase 2 added, all in
DECISIONS.md, each recorded before the runs it affected:

- D3: the baseline on the R610 runs DuckDB 1.4.3, not the
  pinned 2.0.0, whose wheel crashes with an illegal
  instruction on the R610's Xeon E5540 (no AVX). CI keeps the
  locked 2.0.0; all repository tests pass on both.
- D4: the cluster image (CentOS 7 based apache/hadoop:3.3.6)
  needed a yum-based Python install from the CentOS vault;
  Streaming tasks therefore run Python 3.6.8 while the
  baseline runs host Python 3.12.3.
- D5: the stock capacity-scheduler.xml was added to the
  mounted Hadoop configuration; without it the
  ResourceManager cannot start.
- D6: the ladder was re-anchored exactly as
  PREREGISTRATION.md prescribes when a subset target cannot
  be reached: the full corpus (1,984,437,310 bytes, about
  1.85 GiB) is the top rung, labelled full. No threshold, run
  count, or verdict rule changed.
- D7 to D9: harness completions found at first execution:
  the YARN environment variables Hadoop's own error
  prescribed, PYTHONPATH for the localized task files, and
  PYTHONIOENCODING=utf-8 (one discarded pre-fix pass voided
  every cell on Unicode token splits; those rows were
  discarded and re-measured under the final harness, and the
  tokenizer code never changed).
- D10: the H2 small-file cell was stopped by operator
  decision after its warm-up run passed 2.5 hours with about
  640 of 1,055 maps complete (about 117 seconds of map slot
  time per completed map on a mean input of about 1 MiB).
  Three timed runs projected past 20 further hours on a
  shared production machine. The partial counters are
  recorded as observations only. H2 has no verdict from data;
  the results script reports the missing cell as INCONCLUSIVE.
- D11 to D13: Spark environment completions: the absolute
  spark-submit path, world-readable mounts for the Spark
  container's uid, and a standalone CPython 3.8.19 shipped to
  the executors through the distributed cache
  (python-build-standalone release 20240415, SHA-256
  b33feb5ce0d7f9c4aca8621a9d231dfd9d2f6e26eccb56b63f07041ff573d5a5),
  because PySpark refuses the driver 3.8 and executor 3.6
  version split the two frozen images produce. The Spark job
  file, its input, and the H4 comparison are unchanged.
- One further incident: the first matrix launch crashed on
  its first baseline call because results/outputs did not
  exist on the fresh working copy. No timed run had been
  logged and no cell was contaminated; the driver now creates
  the directory, and the matrix was relaunched clean.
- Co-tenancy: the R610's other duties (the Penpot design
  server and system services) stayed live throughout, as the
  brief required. results/host_state.json records the host
  snapshot taken at preflight.

## Grade: 7,750 of 10,000 (final)

Deductions, itemized:

- 1,000: H2 was not measured (D10). One of the four
  hypotheses has no verdict from data. The stop was
  deliberate and documented, and the partial counters are
  published, but the deliverable for H2 is a bounded
  observation, not a measurement.
- 250: the ladder tops out at 1.85 GiB, not the frozen 5 GiB
  (D6). H1 and H4 are decided at a smaller scale than
  planned. The re-anchor followed the pre-registration's own
  rule and was recorded before any timed run, but the
  evidence is weaker than the design intended.
- 200: corpus substitution (D1, carried from Phase 1).
  Forced by the source and fully documented, but the
  abstracts corpus was the brief's first choice.
- 200: the baseline engine on the machine of record is
  DuckDB 1.4.3, not the locked 2.0.0 (D3). The checksum rule
  makes the baseline its own reference, so no verdict can
  drift, but the executed baseline is not the pinned binary.
- 150: the baseline moves token rows into DuckDB through a
  temporary CSV (carried from Phase 1). Honest, documented,
  and now measured: it is part of why the baseline's times
  are what they are at the top rung.
- 150: the two arms did not run the same interpreter (D4):
  Streaming tasks on Python 3.6.8, the baseline on Python
  3.12.3, with one discarded pass lost to a Unicode
  decoding split before the encoding was pinned (D9). The
  final matrix is checksum-clean, so the risk stayed
  theoretical; the asymmetry is real.
- 100: the Spark arm's executor environment differs from the
  Phase 1 description (D13): a standalone interpreter shipped
  through the distributed cache. The job and the comparison
  are unchanged; the provisioning is an addition.
- 100: co-tenancy. The runs shared the machine with its live
  services, as required. Medians of three blunt the effect,
  and the host snapshot is committed, but the cells were not
  measured on an idle machine.
- 100: aborted attempts before the final harness (the
  outputs-directory crash and the discarded pre-fix passes)
  cost machine time and operator rounds, even though no
  contaminated cell entered the run log.

What the grade credits: a locked pre-registration whose
verdict rules decided every tested hypothesis without
interpretation, including two verdicts against the
programme's own expectations (H3's job penalty is zero
within noise; Spark is slower than MapReduce at this scale
on this hardware); a checksum regime that caught a real
tokenizer-environment divergence and voided it before it
could contaminate a cell; and a results file that is
generated, not written, so the numbers in this audit can be
recomputed from the committed run log by anyone.
